# 12 — AI 销售工作台（MVP 演示版）

## 1. 页面目的

AI 销售工作台围绕单个潜在客户提供销售辅助，不是独立聊天机器人。界面采用三栏布局：

- 左侧：线索列表、搜索、Local / Export 过滤、优先级提示。
- 中间：客户上下文、对话记录、常用销售任务、消息输入。
- 右侧：客户画像、现有评分、需求摘要、联系权限和下一步行动。

## 2. 当前实现范围

当前 MVP 使用可解释的本地规则生成建议，不调用真实大模型，不联网研究企业，不自动发送消息。功能包括：

1. 从现有 GET /api/leads 加载线索。
2. 根据所选客户字段生成需求摘要、信息缺口、沟通草稿及下一步计划。
3. Local 与 Export 使用不同的示例表达模板。
4. 将生成建议保存到现有 POST /api/leads/{id}/activities 互动记录。
5. 根据联系权限状态生成内部任务：
   - OPTED_OUT：只创建维护拒绝联系记录任务。
   - 未确认授权：创建核验联系权限任务。
   - AUTHORIZED 或 NOT_APPLICABLE：创建普通销售跟进任务。
6. 调用现有分析接口刷新规则评分。

## 3. 对话数据保存方式

当前对话保存在当前浏览器的 localStorage，按 lead ID 区分。对话不会同步到服务端、不会跨设备共享，也不应存储真实敏感个人信息。用户清理浏览器站点数据后，对话会丢失。保存到客户互动记录的内容则写入当前后端 JSON 数据文件。

## 4. 真实模型接入边界

此版本没有真实 AI 模型调用。正式接入时，建议新增后端 AI Gateway，而不是把 API Key 放在浏览器：

- 前端：POST /api/ai/sales-assistant/messages，发送 leadId、message、conversationId。
- 后端：校验租户与用户权限、读取最小必要客户上下文、检查联系权限、调用模型服务。
- 模型适配：统一 OpenAI-compatible / 自建模型适配接口，模型密钥仅在服务端。
- 返回：assistant message、structured summary、missing fields、suggested actions、usage、model。
- 安全：工具白名单、调用审计、超时及额度控制；未经用户确认不得执行对外触达。

不要把模型输出直接当成已验证事实。企业背景、采购计划、联系人职位、联系方式有效性等需要可信数据源核验。

- [ ] 客户列表可按关键词、业务线筛选。
- [ ] 切换客户后右侧画像和对话上下文同步切换。
- [ ] 对话按 lead ID 在本浏览器刷新后恢复。
- [ ] Local / Export 话术模板区别正确。
- [ ] 未授权客户生成草稿时明确提示先核验联系权限。
- [ ] 拒绝联系客户不会生成营销话术或营销任务。
- [ ] 创建任务后在原有跟进任务页面可见。
- [ ] 保存建议后在客户互动记录中可见。
- [ ] 空数据、API 失败及移动端布局均有反馈。
