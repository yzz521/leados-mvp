# 07 — 合规与安全边界（设计清单）

> 本文是产品工程设计清单，不是针对具体业务、国家或数据流程的法律意见。正式上线前应由法务/隐私负责人按数据类型、目的、来源、国家/地区和实际渠道复核。

## 1. 当前 MVP 安全边界

- 单机单工作空间，无登录和身份认证。
- 没有真正的多租户隔离。
- 没有 HTTPS、CSRF、速率限制、细粒度权限和管理员审计。
- 数据明文保存在本地 JSON 文件。
- 线索删除是硬删除。
- 不连接外部平台，不自动联系客户。

因此：仅在本机或可信测试环境使用；不要导入真实个人敏感信息、客户名单或未获准的联系人数据。

## 2. 数据来源原则

每条线索后续应能说明：

- 数据是谁提供的（用户录入、客户主动留资、授权平台、商业数据供应商等）。
- 取得时间、原始来源和使用许可。
- 收集时的目的和允许用途。
- 是否含自然人个人信息。
- 是否可以用于当前渠道营销。
- 来源授权是否到期或撤销。

“网页可公开访问”并不意味着数据可以无限制抓取、复制、出售或用于营销。对平台条款、数据库权利、个人信息权益和当地营销规定都要单独核验。

## 3. 联系授权状态

当前字段：

- `UNCONFIRMED`：尚未确认，不代表可以联系。
- `AUTHORIZED`：系统记录为已获得授权/请求接收，生产版必须关联具体证据、渠道、用途和时间。
- `OPTED_OUT`：拒绝联系/退订。所有营销工作流必须阻止触达。
- `NOT_APPLICABLE`：只涉及企业信息且当前用途经评估不涉及个人联系人触达；不应作为规避审查的默认值。

正式版建议使用 ConsentRecord 和 SuppressionRecord，不应仅靠一个状态字段管理整个授权生命周期。

## 4. 国内市场需要设计的控制

结合《中华人民共和国个人信息保护法》及相关广告、通信、平台规则，需要按具体场景评估：

- 处理个人信息的合法性基础和明确目的。
- 最小必要、告知、保存期限和安全措施。
- 对公开个人信息的处理仍需落入合理范围和合法条件。
- 自动化营销应提供便捷拒绝方式；自动化决策场景需评估透明度、公平性和相关权利。
- 商业短信、电话营销、平台私信要分别核验相关规则和用户授权。
- 处理敏感个人信息、未成年人信息或向境外提供个人信息时，需额外评估适用要求。

不能把“用户在表单里输入一个手机号”自动推断为同意接收所有渠道和所有类型营销。

## 5. 外贸市场需要分国家/地区配置

至少要建立以下制度化控制：

- 国家/地区识别和适用规则版本。
- 企业法人和自然人联系人区分。
- 联系人数据来源与数据供应商合同审查。
- 商业邮件的发件人身份、主题真实性、地址信息、退订机制及退订处理。
- 直接营销反对/退订状态的同步和阻断。
- 数据跨境、保存期限、删除请求和供应商处理协议评估。

美国、欧盟、英国、加拿大等规则存在显著差异；不要只提供一个全球统一“允许群发”的开关。

## 6. 平台连接器原则

- 优先官方开放平台、客户自有账号授权、官方服务商和合同许可的数据 API。
- 连接器要记录权限 scope、账号授权主体、令牌有效期和撤销状态。
- 不将绕过访问控制、规避验证码、模拟用户批量操作、未经授权抓取等作为核心产品能力。
- 平台接口可用性、权限、配额与审核状态都可能变化，连接器必须允许暂停、降级和替换。

## 7. 自动触达保护

生产版建议将触达做成受控动作：

1. 验证联系人和来源。
2. 检查授权/请求接收证据。
3. 检查退订/拒绝联系名单。
4. 检查国家、渠道和发送频率规则。
5. 对 AI 生成内容执行审核或风险检测。
6. 记录实际发送身份、时间、渠道和内容版本。
7. 处理退信、拒绝、投诉和退订。

默认策略：不确定即停止自动发送，并将任务交给人工确认。
